# 차세대 NPU C-model/ISA (ver.09) 설계 및 구현 보고서

> 2026-08-25 · branch `cmodel-v09`
> 스펙: `d_compiler/ISA_V09.md` · 시뮬레이터: `_poc/mysim_v09.cpp` · 컴파일러: `d_compiler/npu_compiler/backend_v09.py`

## 0. 개요

- **배경**: 기존 vendor C-model(ver.08)의 구조적 한계
  - 단일 평면(flat) 메모리 공간: FP16 전용, 온칩/오프칩 메모리 계층 구분 없음
  - 양자화(quantization) 미지원
  - 오류(범위 초과 접근, 미정의 명령)를 무시하고 진행하는 실행 규약
- **목표**: 아래 3가지를 갖춘 차세대 ISA와 그 참조 시뮬레이터(C-model)를 설계·구현·검증
  - ① 온칩 scratchpad 메모리(SRAM) 기반 2단 메모리 계층
  - ② INT8/INT4 weight 및 activation 양자화 연산 경로
  - ③ 256-lane vector 유닛
- **설계 원칙**: ver.08의 명령어 인코딩(instruction encoding)을 유지하고 필드의 해석만
  확장 → 기존 컴파일러·프로그램 자산과의 연속성 확보
- **검증 원칙(불변식)**: v09의 FP16 모드는 ver.08과 **bit 단위로 동일한 결과**를 내야 함
  → 기확보한 3개 LLM(Llama 3.2 3B / Gemma 4 E2B / Qwen3-4B)의 greedy 생성 결과가
  회귀 검증 기준으로 그대로 재사용됨
- **현재 상태**: 설계 확정, 시뮬레이터·컴파일러 구현 완료, **3개 모델 전부 FP16 모드에서
  생성 token·중간 activation·logits까지 bit 단위 일치 확인**.
  양자화 실측(W8A16/W8A8)이 다음 단계

## 1. 메모리 계층

### 1.1 구조

```
+--------------------------------------------------------------+
|  Global Memory   (off-chip DRAM model)                       |
|    address width  : 32-bit                                   |
|    granularity    : 32-bit word  ->  capacity 16 GiB         |
|    no dtype information (raw data store)                     |
+------------------------------+-------------------------------+
                               |  DMA : GLOAD / GSTORE
                               |  (2D block, dtype-agnostic, blocking)
+------------------------------v-------------------------------+
|  SRAM            (on-chip scratchpad, 8 MiB, single shared)  |
|    address field  : 32-bit (24 effective)                    |
|    granularity    : 4-bit nibble                             |
|    FP32 / FP16 / INT8 / INT4 coexist                         |
+---------------+------------------------------+---------------+
                |                              |
      +---------v----------+         +---------v---------------+
      | Matrix Unit 64x64  |         |  Vector Unit 256 lanes  |
      +--------------------+         +-------------------------+
        (연산 유닛은 SRAM만 접근 — Global 접근은 DMA 경유)
```

### 1.2 주소 체계

| 항목 | Global Memory | SRAM |
|---|---|---|
| 주소 폭 | 32-bit | 32-bit 필드 (유효 24-bit, 상위 8-bit는 0) |
| 주소 지정 단위 | **32-bit word** | **4-bit nibble** |
| 주소 공간 | 2³² × 4 B = 16 GiB | 2²⁴ × 0.5 B = 8 MiB |
| 단위 선택 이유 | 32-bit 주소로 최대 용량 확보 | 최소 데이터 타입(INT4)이 1 nibble → 모든 타입이 정수 개 단위를 차지, 주소 연산이 타입 독립적 |

- 데이터 타입별 폭: FP32 = 8 nibble, FP16 = 4, INT8 = 2, INT4 = 1
- 두 주소 공간의 환산 관계는 단 하나: **Global 1 word = SRAM 8 nibble**
- 바이트 순서(endianness): little-endian으로 고정 — word 내 하위 bit가 낮은 nibble
  주소에 대응하며, host의 little-endian 바이너리와 변환 없이 일치
- 정렬(alignment) 규칙
  - Global에 배치되는 tensor의 각 행: 32-bit word 경계에서 시작, 길이는 word의 배수
  - SRAM에 배치되는 tensor의 시작 주소: 자신의 데이터 타입 폭의 배수
  - DMA의 SRAM 측 주소: 8-nibble(= 1 word) 경계
  - 모델의 tensor 차원이 64의 배수이므로 세 조건 모두 자동 충족; 위반은 컴파일 오류

### 1.3 DMA 전송 (GLOAD / GSTORE)

- 2차원 블록 전송: (행 수 rows) × (행당 word 수 cols), 행 간격(stride)은 별도 지정
- **2차원으로 설계한 이유**
  - SRAM(8 MiB)은 weight 행렬(수십 MB~GB)보다 훨씬 작아 **부분 블록(타일) 적재가
    기본 동작 모드**임 — 예: [8192, 3072] weight의 행렬곱 1회에 64×64 타일 6,144개 적재
  - row-major 저장에서 타일은 1차원 주소상 불연속(행 조각들이 stride 간격으로 반복)
    → 1차원 전송만 있으면 타일당 행 수만큼 DMA 명령 필요, 2차원이면 명령 1개
  - 호스트 사전 재배치(타일 순서 packing)는 정적 weight에만 가능한 대안 —
    실행 중 device가 생성하는 중간 activation과 KV cache(넓은 버퍼에서 유효 열만
    읽는 접근)는 재배치가 불가능하므로 2차원 접근 능력이 필수
  - 비용: rows=1이면 1차원 전송과 동일(상위집합)
- **행 간격(stride)의 의미와 폭**: 전송 블록의 연속된 두 행의 시작 주소 차이,
  즉 원본 행렬의 전체 행 폭. 주소 간 거리이므로 주소와 같은 32-bit 폭을 부여
  - ver.08은 이 필드가 16-bit여서 행 폭이 65,535를 넘는 행렬
    (예: Gemma의 vocabulary 262,144 원소 = 131,072 word)을 표현하지 못했고,
    호스트에서 열 패널로 사전 재배치하는 우회가 필요했음 → v09에서 해소
- 전송은 데이터 타입과 무관한 원본 복사(비트 보존): 압축(packed) INT8/INT4 blob도
  동일 경로로 이동, 해석은 연산 유닛에서만 수행
- 동기식(blocking) 실행 — DMA 완료 후 다음 명령 수행.
  비동기 DMA + barrier(double-buffering용)는 후속 확장 항목으로 명시
- 실행 규약: 범위 초과·정렬 위반·미정의 opcode는 **즉시 오류 종료**
  (ver.08의 무시-후-진행 대비 검증 가능성 강화), HALT(0xFF)가 유일한 정상 종료이며
  종료 시 Global 이미지를 출력해 host가 결과를 회수

### 1.4 컴파일러의 SRAM 운용

- 연산(binding)마다: 피연산자를 SRAM에 적재(GLOAD) → ver.08 방식 커널 수행 →
  결과를 Global로 반출(GSTORE); SRAM 할당은 연산 단위로 초기화(재사용 최적화는 후속)
- 정렬 예외 처리: tensor를 포함하는 최소 word-정렬 구간을 통째로 전송
  (경계에 걸린 이웃 원소는 원래 값 그대로 왕복하므로 결과 불변) →
  홀수 크기/홀수 위치 tensor도 메모리 배치 계획 수정 없이 처리
- SRAM 용량(8 MiB)을 초과하는 tensor(대형 weight 등)는 64×64 타일 또는
  행 패널(row panel) 단위로 스트리밍
- reduction(합/최대)은 256-lane 조각 사이를 FP32 누적기로 연결해
  ver.08의 평면 순차 누적과 **동일한 연산 순서**를 유지 — bit 일치의 근거

## 2. 양자화

### 2.1 수학적 원리

- 양자화: 실수 x를 scale(실수 1개) s와 정수 q로 근사 — x ≈ s·q
- 행렬곱 y = Σₖ a·w 에 대입하면:  y ≈ **(s_a · s_w) × Σₖ(q_a · q_w)**
- 즉 **scale이 누적(Σ) 구간에서 상수인 한**, 정수 곱-누적을 모두 끝낸 뒤
  실수 곱셈 1회로 복원(dequantization)할 수 있다 —
  이 성질이 지원 범위(§2.4)와 하드웨어 구조(§2.3)를 결정

### 2.2 지원 조합 (matrix 연산)

| activation × weight | 통칭 | 곱셈 | 누적기 |
|---|---|---|---|
| FP16 × FP16 | 기본 (비양자화) | FP16 | FP32 |
| FP16 × INT8 / INT4 | W8A16 / W4A16 (weight-only) | FP16 | FP32 |
| INT8 × INT8 / INT4 | W8A8 / W4A8 | 정수 | INT32 |

- 그 외 조합은 오류로 규정
- INT32 누적기 범위 검증: 최악값 (±128)² × K = 2²⁷·⁶ (K = 12,288 기준) ≪ 2³¹

### 2.3 연산 파이프라인 — 반올림 지점은 출력단 1곳

```
SRAM --> [ feeder ] --> [ 64x64 array ] --> [ drain ] --> SRAM
          입력단            곱-누적 배열          출력단
          무손실 형변환만     FP32 또는 INT32 누적   누적값 x scale
          (반올림 없음)                            -> FP16 반올림 1회
```

- 입력단: INT8(−128..127)·INT4(−8..7)는 FP16/INT8에 정확히 표현되므로
  형변환만 수행 — **반올림 없음**
- 출력단: 모든 양자화 조합이 동일한 출력단 하드웨어(FP32 dequant 누적기 + 반올림기)를
  공유; FP16 모드는 출력단을 통과만 함 → 기존 결과와의 bit 일치가 구조적으로 보장
- K방향 그룹 양자화 시: 그룹별 부분합을 FP16으로 중간 저장하지 않고
  출력단의 FP32 누적기에 dequant 후 합산 → 그룹 수만큼 반올림이 누적되는 것을 방지

### 2.4 Scale 세분화 수준 (granularity)

"누적 구간에서 scale 상수" 원칙(§2.1)을 하드웨어에 적용한 결과:

| 지원 | 형식 | 하드웨어 관점 근거 |
|---|---|---|
| ✅ activation | 토큰(행)당 1개, 실행 중 동적 산출 | 출력단에서 행 방향 곱 |
| ✅ weight | 출력 채널(열)당 1개 | 출력단에서 열 방향 곱 (INT8 관행) |
| ✅ weight | K방향 그룹, g ∈ {64, 128} | 곱-누적 배열이 K를 64 단위로 잘라 누적하므로 그룹 경계가 누적 단위와 정렬됨 (INT4 품질에 필수; GPTQ/AWQ의 g=128과 정합) |
| ❌ | g < 64 | 누적 도중 scale 교체 → 배열 내부 로직 필요 |
| ❌ | activation의 K방향 scale | scale이 합산축에 있어 Σ 밖으로 추출 불가 — 수학적으로 불가. 필요 시 host 전처리(SmoothQuant류 scale 재배분)로 해결 |

### 2.5 Activation 동적 양자화 (device 내 수행)

- 절차: |x| 최대값 → scale = max/127 → x/scale 반올림 → 포화(±127) → 압축 저장
- 신규 명령은 압축 저장(VQUANT) 1개; 최대값·나눗셈은 기존 vector 연산 재사용
- 대칭(symmetric) 양자화만 지원 — zero-point 없음 (LLM 관행, 하드웨어 단순화)
- 반올림 모드: round-to-nearest-even (RNE)
- scale은 **FP32**로 저장·전달 (FP16의 표현 하한 6×10⁻⁵ 문제 회피)
- normalization/softmax/RoPE 등 vector 연산은 FP16 유지 —
  LLM에서 해당 연산의 정수화는 정확도 손실로 부적합하다는 것이 일반적 결론

## 3. ISA 변경 및 추가

**원칙: 인코딩 유지, 해석만 확장.**

- 모든 명령은 32-bit word이고, 최하위 byte `[7:0]`이 opcode다
- 아래 비트 필드 그림에서 각 칸의 아랫줄이 **해당 필드의 비트 범위**이며,
  **이름 뒤에 `*`가 붙은 칸이 v09에서 새로 정의된 필드**, 나머지는 ver.08과 동일하다
- `rsvd` = 예약(reserved) 필드, 0으로 기록
- **예약 필드가 전부 0인 ver.08 프로그램은 그대로 유효한 v09 프로그램이다**
  (데이터 타입 00 = FP16, 플래그 0 = ver.08 동작)

### 3.1 기존 명령의 재해석 (인코딩 불변)

**(1) 주소 설정 — opcode 0x80** : 32-bit 주소를 16-bit씩 두 번에 나눠 설정

```
+---------+------+------+----------+--------------------+-----------+
| OPR     | HI   | PT   | rsvd     | ADDR_HALF          | OPCODE    |
| [31:30] | [29] | [28] | [27:24]  | [23:8]             | [7:0]     |
+---------+------+------+----------+--------------------+-----------+
```
- `OPR` 피연산자 선택 (0=src0, 1=src1, 2=dst) · `HI` 상위/하위 16-bit 선택
- `PT` 서술자 종류 (MAIN = 원본 행렬 전체, PARTIAL = 실제 접근할 부분 영역)
- **v09 변경점**: 이 주소의 의미가 "평면 메모리의 원소 번호" → **"SRAM nibble 주소"**
  (필드 위치·폭은 그대로)

**(2) 행/열 개수 설정 — opcode 0x88(행) / 0x89(열)** : 예약 bit에 데이터 타입 추가 (`*`)

```
+---------+------+---------+-----------+------+--------------+-----------+
| OPR     | PT   | rsvd    | DTYPE *   | rsvd | COUNT        | OPCODE    |
| [31:30] | [29] | [28:27] | [26:25]   | [24] | [23:8]       | [7:0]     |
+---------+------+---------+-----------+------+--------------+-----------+
```
- `DTYPE` : `00` = FP16, `01` = FP32, `10` = INT8, `11` = INT4 — **피연산자별로 지정**
  (vector 연산의 피연산자도 같은 서술자를 사용하므로 데이터 타입 지정 경로는 이 한 곳뿐)
- `COUNT` : 행 또는 열의 **원소 개수** — ver.08과 값·단위 모두 동일

**(3) vector 길이 — opcode 0x82** : 형식 불변, 값의 상한만 256 (lane 수)

```
+-----------+--------------+-----------+
| rsvd      | VLEN         | OPCODE    |
| [31:24]   | [23:8]       | [7:0]     |
+-----------+--------------+-----------+
```

**(4) 적재 — opcode 0x90** : 형식 불변, 대상 메모리만 SRAM으로 변경

```
+-------+-------+-------+---------+----------+----------+-----------+
| MTX   | OPR   | STR   | rsvd    | NCOLS    | START    | OPCODE    |
| [31]  | [30]  | [29]  | [28:24] | [23:16]  | [15:8]   | [7:0]     |
+-------+-------+-------+---------+----------+----------+-----------+
```
- `MTX` matrix/vector 유닛 선택 · `STR` 열 방향 stride 접근(전치 적재용)

**(5) 산술 명령 — opcode 0x40~0x43(matrix) / 0x01~0x19(vector)** : 형식 불변

```
matrix
+---------+---------+-------+---------+--------------+-----------+
| MODE    | ACT     | MAC   | rsvd    | IMM          | OPCODE    |
| [31:30] | [29:28] | [27]  | [26:24] | [23:8]       | [7:0]     |
+---------+---------+-------+---------+--------------+-----------+
```
- `MODE` 두 번째 피연산자의 출처(즉시값 / 스칼라 / 벡터) · `MAC` 누적 연결
- `ACT` 융합 활성화 함수: `0` 없음, **`1` = 표준 tanh-GELU (v09 신설)**,
  `2` SiLU, `3` legacy(vendor 근사식)
- **연산 모드(FP16 / 정수)는 피연산자의 DTYPE 조합에서 자동 결정** — 명령에 추가 bit 없음

### 3.2 신규 명령

**(6) DMA 전송 — GLOAD 0xA0 / GSTORE 0xA8** : 4-word 명령

```
w0 +--------------------------------------------+-----------+
   | SRAM_ADDR (nibble unit)                    | OPCODE    |
   | [31:8]                                     | [7:0]     |
   +--------------------------------------------+-----------+
w1 +--------------------------------------------------------+
   | GLOBAL_ADDR   (word unit)                       [31:0] |
   +--------------------------------------------------------+
w2 +--------------------------------------------------------+
   | GLOBAL_STRIDE (word unit)                       [31:0] |
   +--------------------------------------------------------+
w3 +----------------------------+---------------------------+
   | ROWS                       | COLS (words per row)      |
   | [31:16]                    | [15:0]                    |
   +----------------------------+---------------------------+
```
- SRAM 주소의 유효 폭이 정확히 24-bit(= 8 MiB ÷ 4-bit)이므로 opcode word의 예약
  구간에 그대로 수납된다 → 주소 전용 word가 불필요하고, 주소가 명령과 원자적으로
  전달되어 설정 상태가 남는(stale) 위험이 없다
- 부수 효과: 필드 폭이 SRAM 용량과 정확히 일치하므로 **범위를 벗어난 시작 주소는
  표현 자체가 불가능**하다 (해당 오류 경로가 구조적으로 제거됨)
- 실측: 5-word → 4-word 변경만으로 컴파일된 전체 프로그램 크기가
  Gemma −3.13%(6,286,078 → 6,089,609 word), Qwen3 −2.97%(4,004,210 → 3,885,120 word)
  감소 (생성 결과는 bit 단위 동일함을 재확인)

**(7) scale 벡터 주소 설정 — 0x8A(activation용) / 0x8B(weight용)** : 0x80과 동일 형식

```
+---------+------+---------+--------------+-----------+
| rsvd    | HI   | rsvd    | ADDR_HALF    | OPCODE    |
| [31:30] | [29] | [28:24] | [23:8]       | [7:0]     |
+---------+------+---------+--------------+-----------+
```
- 출력단 dequant가 읽을 **FP32 scale 벡터**의 SRAM 주소를 지정

**(8) 양자화 / 복원 — VQUANT 0x1A / VDEQUANT 0x1B**

```
+---------+-------+--------------------+-----------+
| rsvd    | INT4* | rsvd               | OPCODE    |
| [31:28] | [27]  | [26:8]             | [7:0]     |
+---------+-------+--------------------+-----------+
```
- `INT4` : `0` = INT8(포화 ±127), `1` = INT4(포화 ±7)
- VQUANT: FP16 → 정수 압축 저장 (반올림 RNE) · VDEQUANT: 압축 정수 → FP16 복원

**(9) 종료 — HALT 0xFF** : 유일한 정상 종료 명령. 실행 종료 + Global 메모리 이미지
출력(결과 회수 경로). 기존 0xF0은 중간 checkpoint 전용으로 역할을 정리

### 3.3 기존 명령의 예약 bit 확장 (기본값 0 = ver.08 동작)

**배경 — "한 번에 끝나지 않는 계산"을 이어 붙이는 문제**

두 유닛 모두 계산을 여러 번에 나눠 수행해야 하는 상황이 있다.

- **matrix**: K방향 그룹 양자화에서는 64개(또는 128개) 구간마다 scale이 다르므로,
  그룹별로 따로 곱-누적한 뒤 각자의 scale로 복원해서 **합쳐야** 한다
- **vector**: 유닛이 256 lane이므로 3,072개 원소의 합은 12조각으로 나눠 계산해야 한다

이때 중간 결과를 SRAM에 FP16으로 저장했다가 다시 읽어 더하면 **조각 수만큼 반올림이
누적**되고(그룹 48개면 48회), 누적 순서도 원래와 달라져 ver.08과의 bit 일치가 깨진다.

**해결 — 출력단에 FP32 누적 레지스터를 두고 명령으로 제어**

- `CI` (carry-in) : 누적기를 비우지 않고 이번 결과를 **거기에 더한다**
  (`0`이면 비우고 새로 시작)
- `HD` (hold) : 결과를 아직 **내보내지 않고** 누적기에 들고 있는다
  (`0`이면 FP16으로 반올림해 저장)

| CI | HD | 동작 | 쓰임 |
|---|---|---|---|
| 0 | 0 | 새로 계산 → 즉시 FP16 저장 | **ver.08과 동일 (기본값)** |
| 0 | 1 | 새로 계산 → 누적기에 보관 | 사슬 **시작** |
| 1 | 1 | 누적기에 더함 → 계속 보관 | 사슬 **중간** |
| 1 | 0 | 누적기에 더함 → FP16 저장 | 사슬 **끝** |

예: K=192을 64씩 3그룹으로 나눈 그룹 양자화 행렬곱

```
group 0 : matmul --> save(CI=0, HD=1)    ACC  = partial0 x scale0
group 1 : matmul --> save(CI=1, HD=1)    ACC += partial1 x scale1
group 2 : matmul --> save(CI=1, HD=0)    ACC += partial2 x scale2 --> FP16 store
```
→ FP16 반올림은 **마지막 한 번**뿐이다.

**(10) 저장 — opcode 0x98** : 출력단 제어 플래그 3개 추가 (`*`)

```
+-------+-------+-------+-------+-------+-------+-------+------+---------+---------+---------+
| MTX   | rsvd  | STR   | rsvd  | CI *  | HD *  | F32*  | rsvd | NCOLS   | START   | OPCODE  |
| [31]  | [30]  | [29]  | [28]  | [27]  | [26]  | [25]  | [24] | [23:16] | [15:8]  | [7:0]   |
+-------+-------+-------+-------+-------+-------+-------+------+---------+---------+---------+
```
- `CI` / `HD` : 위 표대로 matrix 출력단의 FP32 dequant 누적기를 제어
- `F32` : vector 저장을 FP32 원본으로 수행 — 기본 저장은 FP16 반올림인데,
  scale 값은 FP32 정밀도가 필요하므로(FP16의 최소 정규값이 6×10⁻⁵) 반올림 없이 저장

**(11) 리덕션 — opcode 0x14(합) / 0x19(최대)** : 조각 연결 플래그 추가 (`*`)

```
+---------+-------+--------------------+-----------+
| rsvd    | CI *  | rsvd               | OPCODE    |
| [31:28] | [27]  | [26:8]             | [7:0]     |
+---------+-------+--------------------+-----------+
```
- 원리는 위와 같고, 누적기가 FP32 스칼라 1개라는 점만 다르다.
  리덕션은 결과를 저장하지 않고 누적기에만 남기므로 `HD`가 불필요하고
  (저장은 뒤따르는 별도의 save 명령이 담당), `CI`만으로 사슬이 구성된다
- 합(0x14)은 `CI=0`일 때 0에서, 최대(0x19)는 **첫 원소**에서 시작한다 (§3.4 정정 항목)

```
chunk 0  (elem    0..255) : reduce(CI=0)    ACC  = sum of chunk 0
chunk 1  (elem  256..511) : reduce(CI=1)    ACC += sum of chunk 1
   ...
chunk 11 (elem 2816..3071): reduce(CI=1)    ACC += sum of chunk 11
                            save            --> FP16 store
```
- 결과적으로 3,072개를 한 번에 순차 누적한 것과 **완전히 동일한 연산 순서**가 되어
  ver.08과 bit 단위로 일치한다 (v09 핵심 불변식의 근거)

**추가된 필드 요약** — 전부 기본값 0이 ver.08 동작이다

| 필드 | 위치 | 값 0 (= ver.08) | 값 1 |
|---|---|---|---|
| `DTYPE` | 0x88/0x89 [26:25] | `00` = FP16 | `01` FP32 / `10` INT8 / `11` INT4 |
| `CI` (carry-in) | 0x98 [27], 0x14·0x19 [27] | 누적기를 비우고 시작 | 누적기에 더함 |
| `HD` (hold) | 0x98 [26] | 결과를 FP16으로 저장 | 누적기에 보관 |
| `F32` | 0x98 [25] | FP16으로 반올림 저장 | FP32 원본 저장 |
| `INT4` | 0x1A/0x1B [27] | INT8 (포화 ±127) | INT4 (포화 ±7) |
| `ACT`=1 | 0x40~0x43 [29:28] | (ver.08은 미사용 코드) | 표준 tanh-GELU |


### 3.4 의미 수정 (ver.08 결함 정정)

| 항목 | ver.08 동작 | v09 정정 |
|---|---|---|
| 즉시값 `IMM` [23:8] | 부호 확장 후 unsigned로 재해석 (−3 → 4.29×10⁹) | **signed 16-bit** |
| reduce-max 초기값 | 0에서 시작 → 전 원소가 음수인 입력에서 오답 | **첫 원소에서 시작** |
| vector 저장 길이 | vlen만큼 기록하며 결과 범위 밖을 0으로 덮어씀 | **직전 결과 길이만큼만 기록** |
| 범위 초과 접근 | 읽기는 0 반환 / 쓰기는 무시 | **즉시 오류 종료** |
